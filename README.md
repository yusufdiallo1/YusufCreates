# YusufCreates

A Next.js 16 application with a Convex backend, Stripe billing, Resend
transactional email, and the Anthropic SDK.

**Stack:** Next.js 16.2.12 (App Router) · React 19 · TypeScript (strict) ·
Tailwind CSS v4 · Convex · Convex Auth · Stripe · Resend + React Email ·
Motion · cmdk · ESLint 9

---

## Setup

**Requirements:** Node.js 20+ (developed on 25.9), npm 10+.

### 1. Install dependencies

```bash
npm install
```

### 2. Configure environment

```bash
cp .env.local.example .env.local
```

Fill in the values — every variable is documented inline in
`.env.local.example`. `.env.local` is git-ignored; never commit real keys.

### 3. Initialise Convex

This step has **not** been run yet — it needs an interactive terminal to pick a
team and provision a deployment:

```bash
npx convex dev
```

It will prompt you to log in, create the project, write
`NEXT_PUBLIC_CONVEX_URL` and `CONVEX_DEPLOYMENT` into `.env.local`, and
generate `convex/_generated/`. Leave it running in a second terminal while
developing — it pushes function changes on save.

Then set up auth keys:

```bash
npx @convex-dev/auth
```

Provider secrets (`AUTH_GITHUB_ID`, `RESEND_API_KEY`, …) that Convex functions
read must be set in the **Convex dashboard**, not just `.env.local`.

### 4. Run the dev server

```bash
npm run dev
```

Open http://localhost:3000.

## Environment variables

All are documented with inline comments in `.env.local.example`. Anything
prefixed `NEXT_PUBLIC_` is inlined into the browser bundle — never put a secret
behind that prefix.

### App

| Variable              | Description                                                                  |
| --------------------- | ---------------------------------------------------------------------------- |
| `NEXT_PUBLIC_APP_URL` | Public base URL, no trailing slash. Used for links, emails, OAuth redirects. |

### Convex

| Variable                 | Description                                                |
| ------------------------ | ---------------------------------------------------------- |
| `NEXT_PUBLIC_CONVEX_URL` | Deployment URL. Written automatically by `npx convex dev`. |
| `CONVEX_DEPLOY_KEY`      | Deploy key for CI / production builds. Server-side only.   |

### Auth (`@convex-dev/auth`)

| Variable                                | Description                                                   |
| --------------------------------------- | ------------------------------------------------------------- |
| `JWT_PRIVATE_KEY`                       | Signs auth JWTs. Generated by `npx @convex-dev/auth`.         |
| `SITE_URL`                              | Canonical site URL for callbacks. Match `NEXT_PUBLIC_APP_URL`. |
| `AUTH_GITHUB_ID` / `AUTH_GITHUB_SECRET` | GitHub OAuth credentials (if enabled).                        |
| `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET` | Google OAuth credentials (if enabled).                        |

### Email (Resend)

| Variable                | Description                                              |
| ----------------------- | -------------------------------------------------------- |
| `RESEND_API_KEY`        | Resend API key (`re_…`).                                 |
| `EMAIL_FROM`            | Default From address. Domain must be verified in Resend. |
| `RESEND_WEBHOOK_SECRET` | Verifies Resend webhooks (delivery, bounce, complaint).  |

### Stripe

| Variable                               | Description                                     |
| -------------------------------------- | ----------------------------------------------- |
| `STRIPE_SECRET_KEY`                    | Secret key (`sk_…`). Server-side only.          |
| `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`   | Publishable key (`pk_…`). Safe for the browser. |
| `STRIPE_WEBHOOK_SECRET`                | Verifies webhook signatures (`whsec_…`).        |
| `NEXT_PUBLIC_STRIPE_PRICE_PRO_MONTHLY` | Price ID backing the Pro monthly tier.          |
| `NEXT_PUBLIC_STRIPE_PRICE_PRO_YEARLY`  | Price ID backing the Pro yearly tier.           |

### Anthropic

| Variable            | Description                                    |
| ------------------- | ---------------------------------------------- |
| `ANTHROPIC_API_KEY` | Claude API key (`sk-ant-…`). Server-side only. |

## Architecture

```
src/
  app/
    (marketing)/     public pages — route group, no URL segment
      layout.tsx     header + footer shell
      page.tsx       /
      pricing/       /pricing
    (admin)/         auth-gated dashboard
      layout.tsx     sidebar shell — auth gate goes here
      dashboard/     /dashboard
    api/             route handlers (health, webhooks)
    layout.tsx       root layout: fonts, metadata, globals.css
  components/
    ui/              primitives (button, command-menu)
    marketing/       marketing-only compositions
    admin/           dashboard-only compositions
    motion/          Motion-powered animation wrappers ("use client")
  lib/
    constants.ts     site config, nav
    pricing.ts       pricing tiers and billing maths
    types.ts         shared types
    utils.ts         cn, currency and date formatting
convex/              backend: schema, queries, mutations, HTTP routes
emails/              React Email templates
```

**Route groups.** `(marketing)` and `(admin)` are parentheses-wrapped, so they
group files without adding a URL segment — `(marketing)/pricing/page.tsx`
serves `/pricing`. Each group owns its own `layout.tsx`, which is how the
public site and the dashboard get different shells from one root layout.

**Auth gating.** `src/app/(admin)/layout.tsx` is the single choke point for the
dashboard. Once Convex Auth is configured, redirect unauthenticated visitors
there and every nested route inherits the protection.

**Backend.** Convex functions live in `convex/` and deploy separately from the
Next.js app. `schema.ts` defines tables (`authTables` from Convex Auth, plus
`leads` and `subscriptions`); `http.ts` mounts auth callback routes. Running
`npx convex dev` generates `convex/_generated/`, which gives end-to-end type
safety from database to React — that directory is generated, never edited, and
is excluded from the Next.js typecheck (Convex checks `convex/` against
`convex/tsconfig.json`).

**Path alias.** `@/*` maps to `src/*`, so `@/lib/utils` resolves regardless of
nesting depth. Note it does *not* cover `convex/` or `emails/`, which sit
outside `src/`.

**Client boundaries.** Anything using Motion or cmdk is marked `"use client"`
(see `components/motion/fade-in.tsx`). Pages stay server components by default
and pull client components in as leaves, keeping the JS bundle small.

**Secrets.** Stripe, Resend and Anthropic keys are server-side only — used in
route handlers under `src/app/api` or in Convex actions, never imported into a
client component.
